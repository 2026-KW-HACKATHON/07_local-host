# 점주 UI 구현 및 백엔드 연결 요구사항

기준: 2026-10-07, 현재 로컬 통합 백엔드. 원격 브랜치 최신 API가 있다면 먼저 비교해야 한다.

## 디자인과 화면

Figma `YpZ1g2sdsGYg9MumKPywx3`, 점주 행의 Android Compact - 4, 43, 53, 52, 57, 46, 48, 49, 45를 브라우저에서 확인했다. MCP는 Starter 호출 한도로 사용할 수 없었다. 원본 412×917 구성을 390×844 React Native 앱에 맞췄다. 화면 전체 이미지를 사용하지 않고 실제 입력/버튼/탭으로 구현했다.

- 첫 식당 등록: 이름, 주소, 시작/종료 시간 → 3단계 혜택 초안 설정.
- 제보: 현재 30분 집계, 점주 직접 제보, 상태 선택/확인/성공, 현재 세션의 점주 제보.
- 프로모션: 단계별 혜택 수정, 별도 할인 프로모션 등록/수정/게시·중지/삭제 확인.
- 데이터: 최근 4주 화면과 요일 상세의 빈 상태, 실제 API를 이용한 최근 7일 요일별 막대와 시간대별 선 그래프.
- My: 식당 정보 수정, 휴무 요일 선택, 날짜 달력과 영업 변경 메모, 다른 식당 선택/추가, 로그아웃.
- 활성 탭 검정, 비활성 흰색. 사용자 제공 marketing/point PNG 재사용. 인물과 데이터 막대 아이콘은 네이티브 View. 로고는 기존 원본 대기 슬롯 유지.

식당 검색 공급자가 없으므로 등록은 이름/주소 직접 입력으로 제공한다. 앱 전반의 기존 Noto Sans KR를 재사용했으며 Paperlogy 원본 글꼴/밥줄 로고는 아직 적용하지 않았다. 원본과의 픽셀 단위 일치 완료를 의미하지 않는다.

## 실제 서버 연결

- GET/POST `/api/restaurants`, PUT `/api/restaurants/{id}`. 로그인 점주의 ownerId 일치 매장만 관리 화면에 노출.
- GET/POST `/api/restaurants/{id}/crowd`. 점주 직접 제보는 기존 API로 연결. 손님의 GPS 조건은 변경하지 않음.
- GET `/api/restaurants/{id}/crowd/chart?hours=168`. 현재 최대 조회 범위 168시간.
- GET `/api/restaurants/{id}/promotions/manage`, POST `/promotions`, PUT/DELETE `/promotions/{promotionId}`. 할인율은 기존 계약의 정수 1~100 범위.
- 계정은 실제 회원가입/로그인 후 OWNER 역할로 진입. 하드코딩 계정이나 인증 우회 없음.

## 구현된 입력 UI와 서버 미지원의 구분

3단계 서비스 혜택, 정기 휴무일, 영업 변경 메모는 서버에 보낼 필드가 없다. SecureStore에 **서버 주소·사용자 ID·식당 ID별 초안**으로 보관한다. 저장 메시지와 조회 화면에 기기 초안이며 손님에게 미공개임을 표시한다. 재설치·다른 기기에는 동기화되지 않는다. 로컬 초안을 서버 데이터로 자동 업로드하지 않는다.

현재 세션의 성공한 점주 제보만 목록에 추가하며 고객 닉네임·과거 제보를 꾸며서 표시하지 않는다. 추가 설명은 미지원 안내 상태다.

최근 4주를 요청하는 API를 임의 생성하거나 7일 데이터를 4주라고 표시하지 않는다. 기본 4주 탭은 준비 중/빈 차트이며 사용자가 7일로 전환하면 실제 API 데이터를 표시한다. 7일 통계는 시간별 대표 혼잡도 점수(0/1/2)의 산술 평균이다. 미제보/UNKNOWN은 제외하고 누락 시간 사이 선을 연결하지 않는다. 방문자 수·실제 고객 수 통계가 아니다. 최종 분석 지표는 기획/백엔드 합의가 필요하다.

## 백엔드 팀 요청사항

1. **단계별 프로모션 계약**: 식당별 stage 1~3, 무료 서비스 혜택 문구, 유효 시간/요일, 사용 조건. 현재 퍼센트 할인과 별개다. 음료 서비스를 임의 할인율로 대체하지 않는다.
2. **추천·게시 승인**: Figma의 ‘최근 1시간 바로 앉아요 제보 5개 → 1단계 쿠폰 게시 허용’에 대응하는 추천 ID/근거/기간/단계/수락·거절/게시 상태와 중복 승인 방지. 알림을 통한 해당 승인 화면 진입 및 서버 푸시 계약. 일반 퍼센트 프로모션 게시 확인만으로 이 기능 완료 처리 불가.
3. **영업 일정**: 요일별 영업시간(평일/토요일 등), 정기 휴무 요일, 특정 날짜·기간의 임시 휴무/변경 시간/설명, timezone. 손님 식당 상세에 같은 서버 정보를 제공.
4. **4주 분석**: 28일 날짜 범위 및 timezone, 요일별 값·표본 수·시간대별 값, 집계 지표/가중치/색상 기준, 데이터 없음과 0의 구분. 현재 `hours <= 168`이므로 별도 분석 응답 또는 범위 확장 필요.
5. **제보 목록/설명**: 식당별 최근 제보 목록(표시 닉네임, 역할, 수준, 시각, 설명, 페이지네이션), 점주 추가 설명 저장. 점주 인증과 해당 식당 소유권 검증. 손님 제보의 체류 증명과 점주 제보의 예외를 서버에서 명시적으로 구분.
6. **식당 검색·지도**: 외부 식당 검색 제공자, 주소/위도/경도/층 필드와 식별자 매핑. 좌표를 주소 문자열에서 프론트가 추측하지 않는다.

경로와 DTO는 백엔드 팀과 확정 후 연결한다. 화면은 준비되어 있어도 위 API가 필요한 기능은 서비스 완료 상태가 아니다.

## 수동 검증 방법

Android 실제 앱에서 OWNER로 로그인 → 빈 식당 상태 → 식당 등록 → 단계별 초안 저장 → 4개 메뉴 이동 → 제보 제출 → 할인 생성/편집/중지 → My 수정/휴무/달력 → 7일 통계/요일 상세 → 로그아웃. 실패/빈 데이터 상태, 중복 제출 방지와 하드웨어/화면 뒤로가기를 함께 확인한다. 기존 실제 회원/식당 데이터와 분리한 임시 메모리 DB를 사용한다.
